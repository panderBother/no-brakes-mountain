# 无刹车山路赛车需求与开发计划

版本：V0.8 九关极限递增版  
日期：2026 年 10 月 15 日  
项目暂定名：无刹车山道  
文档用途：确定首版玩法、九关内容、纯代码生成方案、实现顺序和验收标准。

本版变更：九关全部提高起速和加速度，且关卡之间的增幅越来越大。第1关150/+4.20，第6关220/+6.70，第9关286/+9.40，末关理论沿路无碰撞末速约565 km/h。保留渐进柔和转向、无碰撞车损、150 km/h破栏、掉头与超时爆炸；菜单难度标签从高压递进至绝境。

当前状态：28项测试通过。72条多种子参考路线在期限内合法完成；前6关参考路线无碰撞，后3关允许游戏规则规定的轻碰和破栏，不再把零碰撞作为通关必要条件。自动控制器结果不代表真人通关率，桌面包仍未生成。

## 1 项目建议与首版定位

制作一款 **可在浏览器试玩、后续可打包 Windows 桌面版的单人 3D 街机赛车游戏**，采用第三人称追尾视角和程序化山地美术。车辆出发后自动向前行驶、持续加速；玩家用转向、路线选择、护栏或障碍碰撞减速，以及限次时间减速，在规定时间内抵达终点。九关按高速转向、碰撞取舍、复杂弯道、窄路、时间能力、雨雪、断桥、高速综合挑战逐步推进。

玩家需要在三种代价之间取舍：不减速会让弯道越来越难；碰撞只损失少量速度并延长用时，高速撞断护栏后可能失去道路边缘保护；慢动作增加反应时间，但倒计时继续正常流逝。

先做一辆代码生成的赛车、一条可调整的山路和完整的失败重试流程，确认驾驶手感，再扩展九关。项目的主要投入是驾驶手感、赛道设计、程序化视觉和难度调校。建议用清楚的车身轮廓、道路边界、色块、灯光和雾形成统一的低多边形风格。

### 1.1 已确定的需求

- 游戏包含九个关卡，主题和核心难点沿用下文的关卡表。
- 每关从起点驶向终点，车辆不能主动停车、倒车或刹车；允许转向掉头，掉头后沿道路反向行驶。
- 未发生碰撞时，行驶速度持续增加，不采用匀速行驶；允许通过护栏和指定障碍碰撞降低速度，之后继续自动加速。
- 碰撞前模拟速度达到150 km/h时，可撞断室外金属护栏，车辆不会因此损坏。
- 每关限时为理想通关时间加缓冲；截止时刻仍未通关，车辆爆炸并失败。
- 玩家主要控制转向，并在后续关卡使用有限的时间调速能力。
- 九关整体难度逐步上升；场景和声音全部用代码生成，不需要外部模型、贴图、音频文件或素材包。

## 2 玩家体验与操作

### 2.1 一局的流程

主菜单 → 选择已解锁关卡 → 查看限时与规则 → 发车倒计时 → 自动行驶并开始关卡计时 → 判断弯道并转向 → 选择碰撞减速或时间能力 → 限时内抵达终点 → 查看成绩并解锁下一关。

发生失败时，短暂显示撞击、爆炸或坠落效果，随后提供「立即重试」和「返回选关」。失败提示说明原因，例如「高速破栏」「撞断护栏数量耗尽」「超时爆炸」「驶出道路」「错过断桥落点」，帮助玩家调整下一次操作。爆炸演出允许快速跳过，不拖慢重试。

### 2.2 默认按键

| 输入 | 功能 |
| --- | --- |
| A 或左方向键 | 向左转向 |
| D 或右方向键 | 向右转向 |
| 空格按住 | 使用时间减速，松开提前结束 |
| Esc | 暂停或继续 |
| R | 失败或结算界面立即重试 |
| Enter | 确认开始或进入下一关 |

驾驶期间没有油门、刹车、倒车和手刹输入。碰撞减速由驾驶路线触发，没有独立减速按键。暂停属于菜单操作，暂停期间关卡倒计时、成绩、能力时长和冷却全部停止累计。

### 2.3 驾驶手感

车辆应有明确的转向响应和少量惯性。速度提高后，玩家需要更早入弯，短距离内的纠偏余量变少。雨雪通过更明显的横向滑移、较慢的方向稳定过程增加难度。

采用街机驾驶模型，优先保证可预测、可学习和可通关。车辆实际位置由输入和运动计算决定；道路样条用于生成赛道、预警和计算进度，不将车辆强制吸附在道路中心。

首版不加入独立漂移键、氮气、换挡和车辆改装，避免与持续自动加速的主规则争夺操作注意力。

## 3 核心机制规则

### 3.1 自动行驶与持续加速

每关有自己的初始速度和加速度。速度必须作为连续保存的状态，出发后自动增加，发生允许的碰撞时扣减：

```text
开局：v_game = v_start
行驶更新：v_game += acceleration × delta_game
允许的碰撞：v_game = max(v_recovery_min, v_before_hit - speed_loss)
碰撞后：从降低后的 v_game 继续加速，不重设为未碰撞的理论速度
正常时间倍率为 1.0，慢动作时间倍率为 0.35
每个运动步骤使用经过时间倍率缩放的模拟时间增量
引擎内部采用米和秒，速度表中的 km/h 导入时除以 3.6
```

关卡有效行驶期间，加速度保持为正，首版不设置会进入匀速的最高速度平台。车速表显示当前模拟速度 v_game，并真实反映碰撞后的降低。车头角度不设前进范围夹限，沿道路速度允许为负，反向时仍持续自动加速。转向不主动扣除车速；雨雪主要改变横向控制。上坡和松开方向键不会主动减速，碰撞是明确允许的物理减速方式。

每关重新设置起始速度，不将上一关的末速带入下一关。当前九关起速150–286 km/h，加速度4.20–9.40 km/h 每模拟秒，第一关已取消低速教学段。难度递进还需通过实际驾驶表现验证。

护栏与指定障碍的减速结果和高速破栏阈值见第 3.6 节。重复碰撞可以减速，但需要承担时间成本与失去边缘保护的风险，不能靠持续接触在每个物理帧无限扣减速度。

### 3.2 时间减速

时间减速是世界慢动作：车辆、重力、跳跃和相关环境动画按同一倍率运行，给玩家更多现实中的观察与操作时间。时间能力本身不把车辆的模拟速度改小，也不重置加速过程；此时如果发生允许的碰撞，仍按碰撞规则轻微降低速度，不损伤车辆。

| 参数 | 首版建议 |
| --- | --- |
| 解锁关卡 | 第 4 关 |
| 慢动作倍率 | 0.35 倍 |
| 每次最大时长 | 2 秒真实时间 |
| 激活方式 | 新的一次按下空格消耗 1 次 |
| 提前结束 | 松开空格，不退还次数 |
| 再次使用间隔 | 上次结束后至少 1 秒真实时间 |
| 次数补充 | 只在重新开始关卡时恢复 |
| 倍率切换 | 建议约 0.12 秒真实时间平滑过渡 |

单次 2 秒的上限包括进入与退出过渡，临近到期时提前开始恢复，确保到期时倍率已回到 1.0。松开空格时使用相同的短暂退出过渡，仍受本次总时长上限约束。必须松开并重新按下才可再次激活，不能一次长按连续扣次数。冷却从完全恢复正常倍率时开始计算。第 1 至 3 关不提供该能力；后续各关次数见参数表。

只有处于驾驶状态、冷却结束且有剩余次数时，成功激活才扣次数。冷却中、次数耗尽或非驾驶状态下的输入不扣次数、不排队，也不能在条件恢复后自动触发。

关卡剩余时间、能力最长时长、冷却及成绩使用「驾驶期间真实时间」，不受世界慢动作影响；慢动作期间关卡倒计时仍正常流逝。世界模拟时间用于车辆加速与运动。暂停期间两个时钟都停止累计，保存当前倍率、剩余时长和冷却，不能覆盖这些状态。恢复时同步检查空格的实际状态：仍按住则继续剩余时长，已经松开则进入退出过渡。

结束、失败、重试、切换关卡和返回主菜单都必须清理时间状态，恢复倍率 1.0。能力剩余次数和当前倍率应清楚显示。

### 3.3 路面与天气

首版只使用三类路面：干燥柏油、湿滑柏油、积雪或薄冰。差异体现在转向响应、横向滑移和稳定速度，不采用无法预测的随机抓地力。

- 雨夜：降低远景能见度，增加湿滑漂移；靠车灯、路边反光标和弯道标志维持道路可读性。
- 雪山：干燥、雪地、薄冰分区铺设；通过颜色、颗粒和反光区别路面，滑移变化设置短暂过渡。
- 隧道：控制进入和驶出的曝光变化，避免瞬间纯黑或纯白遮挡路线。

重要弯道、窄路和断桥必须有提前可见的线索。建议在正常倍率下保留至少约 1.5 秒的预警时间，并结合车速换算成实际预警距离；这属于待试玩验证的设计目标。

### 3.4 断桥

断桥使用固定起跳坡和明确的落地区域，车辆自动腾空，初始竖直速度继承道路坡度分量后叠加4.3 m/s起跳脉冲，玩家负责起跳前对线与落地后的方向修正。首版不增加手动跳跃键，腾空期间不提供额外横移或推进力。

**慢动作不会让车辆跳得更远。** 相同起跳条件下，统一缩放物理时间不会改变理论飞行轨迹。玩家利用慢动作在起跳前修正方向，可以改变实际走线。桥缝尺寸必须依据本段入桥速度、坡度、起跳角度和落点高度校准；正常时间下也必须存在可成功通过的路线，所用入桥状态必须能从本关起点正常驾驶达到。

慢动作的价值是帮助玩家观察桥口、调整入桥方向，以及落地后迅速应对下一弯。安排断桥之后的急弯，能够形成时间能力的使用决策。

桥前设置清楚的最低起跳速度提示。玩家如果在桥前过度碰撞减速，可能无法跨越桥缝；该最低速度需由桥的实测轨迹确定，不能使用未校准的通用数字。

### 3.5 通关与失败

通关要求从赛道内部正向跨越末端终点，反向行驶不能从起点触发通关，也不能重置倒计时。当前采用连续道路局部进度，不是自由抄近道的开放世界。

超过限时触发车辆爆炸。驶出可行驶区域后坠落、断桥落空仍失败；护栏、路障、岩石碰撞不再扣耐久或直接报废。普通破栏区提供约4米修正带，悬崖约1.5米、桥边约0.7米；这不是无限越野许可，外侧仍有落差风险。

通关与超时同帧时按照跨线时刻判断，终局只能进入一次。合法地面和落地不视为障碍碰撞。

### 3.6 轻碰减速、高速破栏与自由掉头

| 参数 | 当前实现 |
| --- | --- |
| 护栏有效碰撞 | 车速仅减3 km/h，之后继续从降低的速度自动加速 |
| 桶、路障架、岩石碰撞 | 车速仅减4 km/h，障碍一次触发后停用，不损伤车辆 |
| 车损 | 取消碰撞扣耐久、磨栏损伤和车辆撞毁，驾驶界面改为护栏破坏计数 |
| 破栏阈值 | 碰撞前模拟速度≥150 km/h；慢动作仍按模拟速度判断 |
| 护栏破坏范围 | 接触点附近约9米，按3米小段记录；横梁、立柱和反光片消失并产生碎片 |
| 破坏持续性 | 身后片段卸载、掉头返回或重建后仍保留缺口，重试或切关时恢复 |
| 普通公路宽度 | 26–28米，操作得当时可完成150 km/h附近的掉头 |
| 狭窄路段 | 悬崖8.4–8.8米、桥6.8米、隧道5.8–6米，收窄渐变140米 |
| 隧道墙体 | 不可撞穿，碰撞仅轻微减速且保留当前前进/逆向方向 |
| 连续接触 | 合并接触事件，不逐帧叠加速度损失，没有持续车损 |

有效侧碰要求有足够横向撞击速度，门槛约3 km/h；纯粹平行擦过不反复扣速度。低于150 km/h时护栏保持完整并限制横向越界；达到阈值的有效碰撞才撞断护栏。破坏后不再把车辆自动夹回完整护栏内，玩家需要自己修正方向。

键盘/触控先以约23%的小转向起步，持续按住约0.5秒后逐渐达到大转向；100 ms短按的模拟转角由约18°降至约3°。松开和反打快速清除旧输入，暂停、重试时重置输入滤波。转向允许完整360度，车身方向与实际位置自由积分，不吸附道路中心。车体横向占用包含车宽及旋转后的车长，掉头必须真正装得下。推荐靠一侧入弯、提前松开转向消除惯性；在狭窄隧道或过高速度下不保证能掉头。回程会远离终点，计时和加速继续。

逆向时镜头仍在车后，朝向车头；场景预加载窗口转向回程一侧。路障保留少量CPU布局历史，恢复原有位置和已撞状态，可见网格和物理对象仍限制在附近窗口。断桥允许按相同跳跃规则双向通过，慢动作不增加理论跳跃距离。

### 3.7 关卡限时与超时爆炸

每关采用固定限时：

```text
T_limit = ceil(T_ideal + T_buffer)
T_buffer = ceil(T_ideal × buffer_ratio)
T_remaining = max(0, T_limit - t_run_real)
t_run_real = 从发车到本次终局的真实驾驶时间，排除暂停
```

T_ideal 以固定路线、车辆参数下无障碍、无碰撞、无慢动作的理论沿路时间初始化，并通过完整合法参考运行确认。带随机障碍的走线略有额外成本，使用固定缓冲承担；必须执行多个种子的合法完整避障路线，不能通过穿墙、跳过道路或单独赋予速度证明可通关。

T_buffer 给转向误差、适量碰撞减速和时间能力留出容错，不是每次碰撞都额外加时间。使用慢动作、碰撞减速或路段损失都消耗同一份固定时间预算。一次满额 2 秒、0.35 倍的慢动作，在其他运动条件不变且不计过渡时，约增加 1.3 秒真实通关用时；这部分成本应纳入缓冲调校。

缓冲比例从前期较宽松逐步收紧，初值见第 4.2 节。限时在进入关卡时固定，不在玩家变慢、受损或使用能力后动态延长。

发车倒计时结束、车辆开始运动时才开始扣关卡时间；菜单、关卡加载、发车倒计时和暂停不扣时间。剩余时间到零且未通关时，车辆立即进入超时失败，停止接收驾驶与能力输入，播放爆炸特效及音效，再提供重试。

驾驶界面同时显示剩余时间、撞断护栏数量与破栏车速警告。建议最后 20 秒提醒、最后 10 秒红色闪烁提示、最后 5 秒逐秒音效；可关闭强烈闪烁和震动，但保留文字和音效提醒。

## 4 九关设计

### 4.1 主题与核心难点

| 关卡 | 场景 | 核心难点 | 主要设计 |
| --- | --- | --- | --- |
| 1 | 山间公路 | 高速转向与随机避障 | 150 km/h 发车，大幅弯道、宽路随机路障，无慢动作 |
| 2 | 连续 S 弯 | 掌握过弯时机 | 左右切换，逐渐缩短直道，判断碰撞减速的时间代价 |

### 4.3 每关的体验节奏

**第 1 关 山间公路**  
150 km/h 起跑并持续强加速，30 m 初始直段后逐渐进入大弯。110–135 m 出现第一组随机路障，此后需要连续选择线路和纠偏；第一关限时33秒，不能只沿中线硬撞通过。普通路较宽，但障碍会占据部分道路；不能靠不操作或始终按一个方向通关。目标是第一次挑战即有明显压力、需要反复练习，实际通关率必须通过真人统计确认，不预设虚构百分比。

**第 2 关 连续 S 弯**  
依次安排短 S 弯、连续左右切换和收紧的 S 弯。危险来自上一弯留下的方向惯性，玩家需要在出弯时开始准备下一弯。提供少量合适的碰撞减速位置，但反复降速可能超时。通过弯道前的方向标志提供学习依据。

**第 3 关 悬崖公路**  
减少道路余量，引入单侧悬崖。前半段用有护栏的窄路练习，后半段加入可见的护栏缺口；没有护栏的悬崖不能作为碰撞减速点。避免在第一次遇到窄路时同时加入复杂天气和未知急弯。

**第 4 关 九曲发卡弯**  
第一个发卡弯前出现时间能力教学，并预留安全操作空间。九个发卡弯并非都需要慢动作，玩家要选择压力最大的路段使用仅有的两次机会，并决定是否借护栏降低实际车速。两种方式都消耗固定限时，碰撞本身只轻微减速。发卡前后有必要的纠偏距离，不能因高速与过小转弯半径形成必败弯。

**第 5 关 雨夜山路**  
开场先展示车灯和反光标，再进入雨雾和湿滑段。路线通过车灯照亮的路面、反光柱和标志连续可读。滑移是固定可学习的规则，雨粒和闪电不遮挡关键判断。

**第 6 关 雪山险道**  
先展示短的薄冰区，随后组合不同附着力路面和弯道。路面变化提前可见，玩家通过更早转向、小幅修正来应对。薄冰不随机出现，避免失败原因无法复现。

**第 7 关 隧道与断桥**  
建议设置两个断桥挑战。第一处用宽落点教学，第二处要求在较窄落点后接弯。提供三次慢动作，玩家可以将一次机会留给隧道出口或落地纠偏。桥前明确提示最低起跳速度，让玩家判断「过弯前可减速、起跳前需保速」；不要求在完全不可见的桥口盲跳。

**第 8 关 极限盘山路**  
复用前面学过的弯道语言，提升速度、缩短直道并组合连续急弯。达到150 km/h后，撞击可能破坏护栏；减速幅度很小，不能靠连续撞栏迅速刹停。重点测试在高速下提前建立路线和能力分配，缓冲比例进一步收紧。

**第 9 关 最终死亡山道**  
建议依次为山路与窄弯、雨夜湿滑、雪地变化、隧道断桥、最后高速冲线。综合机制采用分段衔接，不把最差能见度、最窄落点和最滑路面同时叠在第一次遇到的障碍上。玩家需保留足够剩余时间进入最后冲刺，末段保留清楚可见的终点，形成破栏坠落风险与超时爆炸的双重压力。

### 4.4 难度调校原则

难度来自速度、弯道频率、道路余量、滑移、碰撞代价、能力分配和限时缓冲。每次调整优先改变一个主要变量，再复测。

每关应记录失败位置、失败原因、碰撞次数、破坏护栏数量、能力使用位置、剩余时间和首次通关尝试次数。找 6 至 10 名不同经验的玩家试玩，用相邻关卡的通关表现验证难度递进。若玩家总因超时失败，要分别检查理想时间是否有效、缓冲是否覆盖合理减速成本、碰撞减速是否过强；若第 4 关因新增慢动作明显变容易，再调整弯道组合。

设计者熟悉路线后的通关不代表新玩家能看清危险；每个高频失败点都要检查预警距离、镜头、路面边界及可通过的转向范围。

## 6 技术方案

### 6.1 网页与桌面共用代码

使用 **JavaScript、Three.js、Vite、HTML/CSS 和 Web Audio**。Three.js 从本地开发依赖构建进发布文件，游戏运行时不加载 CDN。固定依赖版本由 package-lock.json 记录。来源：[Three.js 官方安装说明](https://threejs.org/manual/pages/installation.html)。

游戏专用内容由代码创建；网页版通过本地静态服务或正式静态托管运行。后续 Electron 桌面壳加载同一份 dist/index.html，不需要重写赛道或驾驶规则。当前已准备桌面主进程和构建配置，尚未安装 Electron 或生成、验证 Windows 桌面程序。来源：[Electron 官方分发说明](https://www.electronjs.org/docs/latest/tutorial/distribution-overview)。

当前原型的 GameSimulation 与浏览器渲染分开。车辆运动采用道路局部坐标下的自由转向、偏移和简化跳跃；弯道会在车辆不转向时使其偏出道路，不自动回到中心。碰撞根据车身宽度、道路边缘和动态障碍检测。Three.js 负责真实三维显示，原型采用街机碰撞和轨迹规则，后续再评估是否需要更完整的物理模型。

### 6.2 山路制作

采用「人工设计路线 + 样条生成路面」：

1. 用代码或本地文字配置定义每关中心曲线控制点、高度、路宽、路面与关键事件。
2. 沿曲线采样生成路面网格与碰撞体，处理接缝、坡顶、倾斜和急弯，弯道处适当增加采样密度。
3. 沿道路边缘生成护栏、反光柱和弯道标志；标线与标志使用几何、颜色及代码绘制。
4. 生成道路之外的山体、岩石和树木，保留可行驶路面的净空与危险预警视线。
5. 用程序化模块生成隧道、桥梁、起跳坡与断桥缺口，先验证碰撞和可通过性。

levels.js 为固定路线计算中心线、坡度、方向和曲率，提供按距离采样的接口。renderer.js 据同一套数据生成路面顶点、护栏、桥隧和装饰；core.js 据路宽、边界和危险区域进行碰撞及进度判断。路面使用 Three.js BufferGeometry，重复场景物件使用 InstancedMesh。

赛道是固定、可复现的手工设计路线。首版不在玩家行驶过程中随机生成弯道。

道路和地形在关卡加载阶段创建，驾驶中复用生成结果。地形需要明确避开桥缝、悬崖坠落区和隧道内部，不得自动填平断桥或遮住可见道路；断桥缺口必须同时缺少路面网格和桥面碰撞。

### 6.3 时间机制实现

GameSimulation 将真实增量按不超过 1/120 秒拆分，驾驶运动使用 scaledDt = realDt × timeScale。关卡限时、成绩、能力时长和冷却使用未缩放的真实增量；持续磨栏和跳跃使用模拟增量。暂停时停止累计这两种时间，保留并正确恢复能力状态。

网页通过 requestAnimationFrame 更新渲染，浏览器切到后台或窗口失焦时自动暂停，避免玩家看不到画面时仍扣时间。慢动作倍率只在核心运动处应用一次，不重复缩放位移。Web Audio 的合成引擎音独立按速度与状态调整，倒计时提示音按真实时间播放。

障碍配置包含碰撞类型、固定速度损失、是否可破坏和连续接触组。高速破栏读取碰撞前的速度快照，不能先减速再判断阈值。护栏减速只处理有效接触事件，不产生持续车损；正常路面与落地单独分类。

当前工程将职责分配到 levels.js、core.js、hazards.js、renderer.js、scene_chunks.js、audio.js 和 main.js。预览版按连续道路进度判定终点，没有独立复活检查点；正式版若扩展真实自由地形驾驶，再增加独立进度门防止跨路段抄近道。

### 6.5 性能目标

首版目标是在事先约定的 Windows 测试机上，1080p 中等画质达到约 60 FPS。测试机配置需在原型阶段记录，当前不承诺未知硬件的表现。

采用分段几何、重复物体实例化和按距离调整装饰。路线采样轻量常驻，三维场景沿玩家进度渐进生成，前方提前加载、身后释放；共享材质和基础几何复用，独立道路几何和实例缓冲卸载时销毁，不一次构建整关三维场景。雨雪限定在玩家附近；视觉爆炸碎片和装饰不参加驾驶碰撞。先检查隧道出入口、雨夜、桥梁及大量树木的压力场景。

程序化音频应限制同时发声数量和生成成本，合成声音需保持连续缓冲；性能验收同时检查驾驶帧率、关卡加载时间和声音是否断续。

## 7 纯代码内容生成方案

### 7.1 制作约束

所有游戏专用视觉内容、交互界面和基础音效由项目源码生成。工程不依赖外部 GLB、FBX、OBJ、图片贴图、录音、音乐、图标包或下载字体；不用第三方素材生成服务或美术插件。游戏运行不请求远程资源。

允许使用本地打包的 Three.js 几何、材质、灯光、实例化接口，浏览器绘图和 Web Audio，以及自写脚本、着色器和关卡数据。生成结果保存在内存，由 WebGL 渲染。发布文件保留 Three.js 的许可说明；后续桌面包同样保留对应依赖许可。

### 7.2 各类内容的生成方式

| 内容 | 代码生成方式 | 首版表现目标 |
| --- | --- | --- |
| 赛车 | 盒体与自定义低面数网格构成车身、车窗、尾翼；圆柱构成四轮 | 清楚的车身比例，轮胎旋转，转向可见 |
| 山路与标线 | 固定曲线采样后生成带宽度的路面；线条用窄网格或程序化着色 | 连续弯道、坡度、清楚边界与路面类型 |
| 护栏与可撞路障 | 沿道路生成横梁和立柱；圆柱、盒体组合成路障桶或轮胎堆 | 可撞对象形状稳定，轻微减速与护栏碎裂反馈明确 |
| 山体与悬崖 | 三角网格、山脊控制点与有限噪声生成轮廓和坡面 | 道路上下有可辨的高度关系，悬崖留出坠落区域 |
| 树木与岩石 | 圆柱树干、锥形或块状树冠；低面数顶点扰动形成岩石 | 重复几何配合尺寸和颜色变化，形成山地环境 |
| 隧道与桥梁 | 重复截面形成洞壁，盒体与支柱构成桥梁；主动省略断桥区域 | 洞壁、桥面和起跳坡与碰撞严格一致 |
| 雨雪与雾 | 雨用细线、雪用小几何粒子；雾与灯光通过引擎和代码参数控制 | 天气可见，危险路线仍能提前识别 |
| 湿滑与积雪表面 | 颜色、粗糙度、坡度遮罩和自写噪声着色 | 与路面附着力分区匹配，无图片贴图 |
| 火花与爆炸 | 发光小几何、扩张亮球、烟粒子及限量视觉碎片 | 撞击和超时爆炸立即可辨，数量有上限 |
| 界面与图标 | 用代码创建文字、按钮、进度条及几何绘图 | 中文可读，剩余时间与危险速度突出 |
| 声音 | 数学波形、噪声与音量包络在内存中合成 | 引擎、风声、擦碰、能力、倒计时和爆炸的街机音效 |

renderer.js 用自定义网格及 Three.js 基础几何构造车辆、山体、树木、道路和桥隧，按道路分段渐进生成并复用共享材质；重复树木与护栏通过实例化减少绘制开销。来源：[Three.js 官方 API 文档](https://threejs.org/docs/)。

audio.js 使用浏览器 AudioContext、振荡器、增益包络、滤波器与内存噪声合成引擎、风声和短事件音，不下载音频。声音在玩家点击开始或开启声音后初始化，受浏览器音频权限和用户音量设置约束。

字体使用 CSS 系统字体栈，优先 Windows 中文字体和等宽数字字体，浏览器进行回退，不在工程中加入下载字体文件。目标测试设备仍需检查中文菜单和提示是否完整显示。

### 7.3 固定路线、动态路障与主题变化

九关路线、坡度、路宽、路面分区、护栏缺口、隧道、桥缝和终点固定。每次发车选择新障碍种子，按道路进度在前方 380–500 m 范围生成路障，身后 80 m 的记录回收。显式传入相同种子可复现完整布局，不同帧率和推进步长不能改变该布局。

路障采用桶、岩石和路障架的组合，每组留至少3.6 m净空通道，最窄隧道留3.8 m；宽路通道可分布在中线两侧约7.2 m，干路相邻组中心变化最多5 m，湿地4.2 m、雪地3.6 m、薄冰2.6 m。干路组距52–80 m、湿地66–94 m、雪地78–106 m、薄冰90–118 m。断桥前180 m、后220 m禁障，隧道入口和出口附近也留过渡净空。禁止随机封路、在车旁突然生成或用装饰充当不可见碰撞体。最好成绩记录关卡、时间、种子和规则版本。

场景装饰使用稳定种子。连续山脊与谷地、岩壁切面、森林层次、雪地和薄冰、湿路反光、窄隧道的拱顶和照明、桥梁支撑与断口分别突出主题。天气、路面视觉与实际附着力分区保持一致。所有纹理由代码绘制或噪声产生，不导入图片。

全工程共享车身尺寸、道路尺度和材质规则。可撞桶、路障架与岩石应能从外观辨认，所有障碍碰撞均不损伤车辆。普通道路宽并不降低高速绕障需求；隧道和桥面通过明显的边界和渐变入口提供收窄线索。

### 7.4 生成与验证顺序

1. 创建几何和材质工厂，生成一辆车、护栏、树木与岩石的基础版本。
2. 由固定曲线生成测试路面与碰撞，验证正常行驶、坡顶、急弯和护栏接缝。
3. 生成山体与装饰，检查道路净空、桥缝和悬崖留空区域。
4. 加入代码创建的界面、基础合成声音、天气与爆炸。
5. 在每种关卡主题中检查外观、碰撞、危险预警、声音与性能，再记录参考通关路线。

首版素材采购预算为 0。取消素材寻找、下载和导入工作，开发投入改为程序化模型、材质、音效与调校；纯代码方式仍需要完成视觉设计和完整测试。

### 8.1 第一轮原型的具体任务

第一轮由代码生成一辆几何赛车、一条带缓弯和坡度的山路、护栏、路障及简洁山地环境；实现自动加速、左右转向、碰撞减速、无碰撞车损、高速破栏、关卡倒计时、超时爆炸、失败重试和基础界面，再加入短合成音效。

原型需要回答：键盘是否容易纠偏、速度增长是否带来压力、碰撞降速是否有用且有代价、剩余时间是否让玩家做选择、高速破栏是否提前可知，以及失败后是否愿意立即再试。确认这些成立后，再增加第 4 关的慢动作测试路段，以及第 7 关的一处灰盒断桥。

## 9 验收标准

以下是正式版的验收标准。网页原型已完成核心规则自动化测试与浏览器基础检查；完整验收状态、真人手感、正式性能和桌面发行仍需后续验证，测试范围见独立的网页版测试记录。

| 编号 | 验收内容 | 通过条件 |
| --- | --- | --- |
| A01 | 自动行驶 | 倒计时结束后无需油门即可前进，无刹车和倒车输入 |
| A02 | 自动加速与碰撞降速 | 两次碰撞之间模拟车速持续增加；碰撞后从降低的速度继续加速，下一帧不会恢复旧理论曲线 |
| A03 | 转向与路面 | 干燥、湿滑、薄冰的控制差异可复现，路面变化提前可辨 |
| A04 | 时间能力 | 第 1 至 3 关不可用；后续按关卡配置供给；一次按下只扣一次 |
| A05 | 时间时长 | 单次最多 2 秒真实时间，建议误差不超过 0.05 秒；提前释放不退次数 |
| A06 | 时钟与暂停 | 慢动作不缩放限时、成绩和能力时长；暂停不扣时间、能力或耐久，继续后状态正确 |
| A07 | 状态恢复 | 能力使用中失败、重试、切关和返回菜单后，倍率恢复正确，无残留慢动作 |
| A08 | 断桥 | 入桥状态能从本关起点正常达到；正常倍率可通过；相同起跳条件下慢动作不额外改变飞行轨迹或跳跃距离 |
| A09 | 九关与进度 | 九关主题和机制符合计划；预览九关可直接试玩并保存通关记录；正式挑战可顺序解锁，不能跨相邻发卡路段误触终点 |
| A10 | 失败与重试 | 超时、坠落和断桥落空等原因准确；重试恢复起速、完整限时、能力和进度，修复全部护栏并清理接触状态 |
| A11 | 本地保存 | 关闭并重开游戏后保留解锁、最好成绩和设置；损坏存档可安全恢复默认 |
| A12 | 路线公平性 | 每关存在无碰撞、无慢动作的合法完整参考路线；正常玩家使用减速策略也有合理限时容错；危险可见，弯道、路宽及转向范围匹配 |
| A13 | 可读性 | 雨雪和隧道不遮挡关键路线；车速、剩余时间、破栏统计、破栏车速和能力提示清晰 |
| A14 | 性能与运行 | 约定测试机上的目标画质达到目标帧率；发布包可离线启动和游玩 |
| A15 | 纯代码与依赖 | 不依赖导入的模型、图片、音频、自定义字体或远程素材；内容由代码和本地配置创建，发布包保留引擎与内置组件许可 |
| A16 | 碰撞与阈值 | 护栏只减3 km/h、障碍只减4 km/h，不扣耐久；撞前达到150 km/h破坏室外护栏，正常及慢动作判定一致 |
| A17 | 连续接触 | 同一连续护栏只触发一次初始减速；接缝不重复触发，没有持续车损，30、60、120 FPS 接触合并结果一致 |
| A18 | 固定限时 | 理论沿路时间与合法参考时间核对后取整，加固定缓冲；随机绕障、碰撞与慢动作不延长限时；到期未过终点爆炸 |
| A19 | 截止时刻与终点 | 截止时刻前或恰好截止时刻有效跨线可通关；同帧越线与超时按事件时间判定，通关后不再爆炸 |
| A20 | 停滞与障碍分类 | 不因掉头的横向或逆向运动误判停滞报废；路面和合法落地不触发减速，所有障碍碰撞不伤车 |
| A21 | 带种子的动态生成 | 同一关卡与种子可复现；普通重试更换种子；所有布局留合法通道并避开桥口安全区 |
| A22 | 几何与碰撞 | 路面、坡顶、隧道、护栏和桥缝的可见形状与碰撞一致，桥缝不被地形填平，装饰与粒子不影响驾驶 |
| A23 | 离线与文字 | 无需外部素材缓存、下载或网络即可生成并游玩九关；目标 Windows 系统字体下中文界面显示完整 |
| A24 | 合成声音 | 基础声音全由代码生成；无明显断音、爆音或无限叠加，音量可调，倒计时音与真实时间一致 |
| A25 | 渐进场景 | 只常驻邻近片段，前方无道路缺口；身后卸载数量增加，网格、纹理和实例缓冲长期稳定 |
| A26 | 掉头与逆向 | 150 km/h附近可在普通宽路完成无碰撞掉头；进度随后减少，镜头和加载窗口反向，计时继续 |
| A27 | 破栏持久性 | 缺口、立柱和反光片正确隐藏，卸载重载后仍存在，重试恢复，车辆不因撞栏爆炸 |

测试还应覆盖 30、60、120 FPS 条件下的运动与轻微碰撞减速一致性、连续磨栏、跨护栏接缝、重复撞击、阈值上下的车速、慢动作中撞击、空格长按、能力耗尽、暂停与重试、剩余时间到零、终点与超时同帧，以及慢动作中的起跳与落地。每关执行多种子合法参考路线和真人试玩并保留理想时间记录；较低帧率下检查碰撞穿透、停滞误判和断桥落点。

试玩记录要区分「操作失误」与「看不清」「碰撞错误」「物理不可过」。后三类问题优先修复，不能解释为关卡难度。

## 10 主要风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 无刹车与急弯组合导致必败 | 按该路段实际速度验证转向范围，调整半径、弯间距、路宽或加速曲线 |
| 碰撞减速下一帧失效 | 保存当前速度并在其上积分加速，不用未碰撞理论曲线覆盖状态 |
| 贴栏无限减速或停车 | 合并接触事件，只轻微减速，无车损，横向掉头和反向行驶不能误判停滞 |
| 高速撞击先减速后判定 | 使用碰撞前速度快照判断破栏，随后执行固定3 km/h轻微减速 |
| 慢动作改变破栏阈值或冻结倒计时 | 按模拟车速判断护栏破坏，限时使用排除暂停的真实时间 |
| 理想时间过短或无法实测 | 先验证合法无撞无慢动作参考路线，再实测并配置缓冲 |
| 缓冲过宽使碰撞成为单一最优策略 | 联合调校轻微降速幅度、破栏风险与限时，测试不同减速选择 |
| 断桥只能靠错误时间缩放通过 | 在正常倍率下先验证起跳和落地，慢动作仅辅助操作 |
| 雨夜靠遮挡制造难度 | 保留反光标和足够预警距离，将挑战主要放在判断与滑移 |
| 九关重复或难度顺序失真 | 每关引入明确的技能要求，记录试玩表现后调校相邻关卡 |
| 程序化物件重复、道路不可读 | 统一尺度与色板，用轮廓、光照、密度和主题区分，优先清楚道路边界 |
| 道路网格、护栏与碰撞错位 | 从同一组路线采样数据生成，检查急弯、坡顶、桥缝和模块接缝 |
| 山体填平断桥或遮住隧道 | 显式配置留空区域和道路净空，逐段驾驶验证 |
| 生成卡顿或合成声音断续 | 加载阶段构建并复用网格，限制装饰与粒子，控制音频采样和发声数量 |
| 随机路障封路或突然出现 | 带种子提前生成，限制通道变化，保护桥口并执行多种子驾驶验证 |
| 过早做全套场景导致返工 | 先灰盒验证车辆、第 1 关、慢动作与断桥，再增加装饰 |
