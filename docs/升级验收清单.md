# 山道赛车升级验收清单

日期：2026 年 10 月 14 日。针对高难度、随机路障、分块加载与场景辨识的可执行验收。

## 1. 高难度仍可完成

- [ ] 起步速度、加速度明显提高；第一关不转向会失败，保持居中也不能无视随机障碍通关。
- [ ] 第一关连续试玩 10 次，记录失败位置、原因和用时；检查失败来自可见弯道或路障，不来自入口瞬间缩路、生成在车上或没有避让通道。
- [ ] 多个固定随机种子、九关使用合法输入的参考驾驶能完成。参考驾驶不修改车速、位置、耐久或限时；其成功说明有可行路线，不能宣称真人通过率已验证。
- [ ] 记录最大转向需求 `abs(curvature) * speed / 3.6 / steeringRate(speed, surface)`；大曲率、高速、冰雪组合仍有修正余量，并由完整参考驾驶确认。
- [ ] 普通道路加宽，隧道、悬崖变窄；宽度平滑过渡，渲染边缘、护栏碰撞与核心采样宽度一致。
- [ ] 首关的初始直道足以认清前路。隧道入口在缩路前可见，不能把玩家原本合法的位置直接判为撞栏。

## 2. 随机障碍与时间预算

- [ ] 同一关、同一种子生成完全相同的路障；普通重试使用新种子，显式传入种子可以复现测试或回放。记录显示当前种子。
- [ ] 路障按照前路距离生成，绝不在车旁或已越过位置突然出现；至少提前约 1.5–2 秒可见，雨夜和冰雪适当增加。
- [ ] 每组障碍保留完整可驾驶通道，通道宽度应大于车宽并有修正余量；相邻组错侧时提供足够变线距离，不能只检查单组横截面。
- [ ] 隧道入口、断桥起跳区、断桥落点留安全区；窄路不出现跨满道路的障碍组合。
- [ ] 首发、随机重试、显式种子复现分别检查路障的碰撞与可见位置；撞过的桶只触发一次，重试恢复。
- [ ] 限时以合法路线的参考用时加缓冲校准，不能继续使用提高速度前的理想时间；抽查不同种子的绕障成本。
- [ ] 使用时间能力时赛道时钟继续消耗真实时间，碰撞报废使用碰撞前的模拟车速；临近截止通过终点和超时爆炸各检查一次。
- [ ] 成绩保存包含规则版本与路线种子。更新规则后旧成绩单独处理，不能与新难度记录直接混用。

## 3. 分块加载与资源回收

- [ ] 开始、重试和跳至中途检查：当前车位、前方预警距离、后方镜头范围内道路已经就绪；推进到下个块前不会露出空路。
- [ ] 通过块边界观察道路标线、护栏、隧道顶棚和地形没有接缝；断桥开口不被相邻块补回。
- [ ] 同一块卸载后重新进入，山体、树木和路障布局一致；分块各自使用稳定随机状态，不因画质、载入顺序或镜头位置改变碰撞布局。
- [ ] 使用诊断入口 `window.__mountainGame`，记录活动块数量、待加载数量、已加载道路范围、draw calls、triangles 和几何资源数量。
- [ ] 沿长关逐段行驶，活动块保持在配置上限以内；到达终点时几何资源应处于稳定区间，不能随已经过的总里程增长。
- [ ] 重试 10 次、九关来回切换 3 轮后，几何与材质数量回到同一场景的稳定区间；允许渲染器内部缓存，但不能每轮固定增长。
- [ ] 审查卸载实现：移除场景节点，同时释放块专属 geometry/material；共享材质只在最终退出时释放。已卸载路障的 mesh 映射也清除。
- [ ] 画质高/低切换后前路完整；后台恢复和长帧之后不会在车位附近补生成路障或漏载道路。
- [ ] 本机浏览器连续驾驶至少 60 秒，记录窗口尺寸、画质与帧耗时中位数/P95；分别报告生成峰值与稳定驾驶，不以截图代表帧率通过。

## 4. 场景辨识与画面

- [ ] 山间公路：山体层次、路肩、弯道方向明确；车辆、路障与道路边缘形成清晰视觉层级。
- [ ] 连续 S 弯与发卡弯：镜头可以预读转向，不只靠左右按键试错；相邻山路互相遮挡时无穿插地形。
- [ ] 悬崖：路侧落差明显，可见栏杆缺失区；车轮驶出道路后的失败与画面一致。
- [ ] 雨夜：湿地反光、雨线与路灯/反光标明显，路障仍可在反应窗口内辨认。
- [ ] 雪山：雪面与冰面视觉区别明显，抓地力变化可以预判；白色背景不会吞掉路缘与路障。
- [ ] 隧道与断桥：隧道明显收窄、洞口和内部照明可辨；顶棚不挡驾驶镜头，起跳与落地位置可读。
- [ ] 极限与最终关：连续急弯、高速与多种天气机制可辨，警告信息不过度遮挡前路。
- [ ] 1440×900、1366×768、390×844 检查驾驶仪表和菜单；转向、时间能力、暂停等按钮可触达，页面无横向溢出。
- [ ] 检查网络请求均为本地构建资源，无远程模型、贴图、字体或声音依赖。

## 执行与留证

本轮负责核心与渲染实现的人运行 `npm test` 和 `npm run build`；独立审查仅追加尚未覆盖的多种子路径、资源增长和浏览器场景检查，已通过且未修改的检查不重复运行。失败条目记录关卡、种子、车速、里程、画质、复现步骤与截图，修复后复查对应条目。

## 已完成的独立静态复核

- 九关按无碰撞理论车速计算，最大弯道转向需求/可用转向能力之比为 0.284、0.342、0.401、0.570、0.533、0.602、0.495、0.652、0.709；最不利点仍有约 29% 角速度余量。完整路径是否可完成另由核心参考驾驶检查。
- 9 关 × 32 种子共 288 组、11,888 个路障：没有侵入声明通道、越出道路，或进入断桥前后 150 米保护区的路障。物理常驻最多 16 个路障，最小组间距 88.01 米，最大相邻通道中心位移 3 米。
- 正常逐段推进时，初始预置路障之后新生成的路障至少在前方 380.86 米。这个数值表示生成距离，实际可辨认的距离仍需检查雾、转弯遮挡与渲染加载范围。
- 72 组关卡/种子分别以每 3 米、每 47 米推进生成，完整路障位置、类型与通道指纹一致；更新节奏不改变固定种子的布局。
- 稀疏路线检查未发现相隔至少 90 米的路段发生道路宽度重叠。第 7 关最窄 6 米，第 9 关最窄 5.8 米，采用 45 米平滑收窄。

以上针对本轮核心与路障生成代码，不代表真人低通过率、GPU 资源回收或帧率已经验收。

## 分块对象生命周期复核

用真实 Three.js 对象和模拟 Canvas 2D 环境，在 Node 中依次加载九关、每 16 米推进并跳转到起点、中途与终点，检查分块调度和 `dispose` 事件。没有创建 WebGL 上下文，也没有操作实际试玩浏览器。

- 活动块最多 9 个，低于配置上限 11；路障实体最多 14 个，队列最多 4 个；当前车位未出现缺块。
- 跟踪了 1,802 个几何对象和 3,557 个 InstancedMesh。最终销毁时，块专属几何、共享几何、实例对象、材质与纹理均释放，场景赛道组清空。
- 该轮 Node 单块生成 CPU 耗时中位数 2.36 ms、P95 3.95 ms、峰值 13.56 ms。每帧队列最多生成 2 块，并检查 5.5 ms 的软预算；单块构建不可中途打断，不能把这个预算写成严格帧耗时上限。
- `renderer.clearTrack()` 已接入分块清理，天气资源单独释放，未发现逐块误释放共享材质或纹理。完整退出时的常驻爆炸 InstancedMesh 和灯光阴影 render target 释放遗漏已修复；真实 renderer 原型与 Three 对象检查确认它们各释放一次，共享几何与材质只释放一次，天气和场景清空。
- 九关各自检查第 0、5 块，卸载后返回重建，18 组顶点、法线、UV、颜色与实例变换指纹一致，载入顺序不改变这些块的地形与植被。

以上验证的是对象所有权与释放调用。实际显卡计数、阴影/环境贴图缓存、帧率及前方路障可见距离需要由浏览器诊断验证。

最终桥坡平滑与地形三角形支撑修改后，专项复查 242 块生成：Node 单块中位数 2.73 ms、P95 4.46 ms、峰值 17.02 ms；12,117 次支撑扫描累计 27.04 ms。新 CPU 顶点数组仅归活动块持有，最多 41,472 个数值（约 332 KB 数值负载，不含数组容量与对象开销）；242 次卸载均置空，未发现其他数组常驻引用。这个专项复查未重复运行核心与旧多种子验收。
